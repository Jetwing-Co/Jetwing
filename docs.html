Getting Started

Jetsidian is an injectable Minecraft client that runs on Lunar Client and vanilla Minecraft. You can grab access through our Discord server.

Once you've got your license key, download the injector and just follow the injection guide below, its honestly really simple.

Injection

Jetsidian injects directly into a running Minecraft process. Supported launchers:

  • Lunar Client
  • Badlion Client
  • Vanilla Minecraft

Steps

  1. Launch Minecraft through your chosen launcher and get to the main menu.
  2. Open the Jetsidian injector.
  3. Enter your license key and log in.
  4. Click Inject.
  5. Press Right Shift to open the module panel.
The injector must be run as Administrator on some systems. If injection fails, right-click the injector and select "Run as administrator".

GUI & Modules

Right Shift opens the panel GUI. Click "Edit Positons" to drag modules to reposition them. Click a module to toggle it. Right-click for per-module settings and keybind options.

A legacy GUI is also available, search "legacy GUI" in the Panel and click it. To go back to Panel, click the Panel module.

Scripting API

Scripts are .java files you drop in a folder. The client compiles them while the game is running and turns each one into its own module you can toggle in the GUI. You write normal Java and get a large built-in API draw things, read the world, send packets, react to chat, move the player, and more. You can reload scripts on the fly while testing.

If you've written any Java before, you already know 90% of this. If you haven't, the Auto GG tutorial below teaches you enough to get started.

Setup

You need a JDK installed, not just a JRE. The client compiles your script with the real Java compiler at runtime. If only a JRE is present, scripts won't compile.

Where scripts live:

%APPDATA%\.minecraft\jetsidian\scripts\

Every .java file in that folder becomes a module. Files whose name starts with an underscore (e.g. _WIP.java) are skipped.

Reload loop: edit file → reload scripts → toggle the module → test. Only changed files recompile, so reloads are fast.

Tutorial: Build "Auto GG"

We'll build a script that automatically types "gg" in chat when a game ends, growing it step by step.

Step 1 Prove it loads

Create AutoGG.java in the scripts folder. You write only the class body no class declaration needed.

void onEnable() {
    client.print("&aAutoGG loaded!");
}

Reload scripts, enable the module. You'll see a green message in chat. &a = green, &c = red, &e = yellow, &b = aqua.

Step 2 Hook incoming chat

boolean onChat(String message) {
    client.print("CHAT: " + message);
    return true;
}

return true = let the message show. return false = hide it. Hooks are declared by method name + parameter count no registration needed.

Step 3 Detect game end

String[] triggers = { "Winner:", "1st Killer", " won the game", "1st Place" };
 
boolean onChat(String message) {
    String msg = util.strip(message);   // remove colour codes first
    for (String t : triggers) {
        if (msg.contains(t)) {
            client.print("&eGame end detected!");
            break;
        }
    }
    return true;
}

Step 4 Delayed send with tick countdown

Never sleep the main thread. Count ticks instead 20 ticks = 1 second.

String[] triggers = { "Winner:", "1st Killer", " won the game", "1st Place" };
int sendInTicks = -1;   // -1 = idle
 
boolean onChat(String message) {
    String msg = util.strip(message);
    for (String t : triggers) {
        if (msg.contains(t)) { sendInTicks = 20; break; }
    }
    return true;
}
 
void onPreUpdate() {
    if (sendInTicks < 0) return;
    if (sendInTicks == 0) client.chat("gg");
    sendInTicks--;
}

Step 5 Fire only once per game

String[] triggers = { "Winner:", "1st Killer", " won the game", "1st Place" };
int sendInTicks = -1;
boolean armed = true;
 
boolean onChat(String message) {
    if (!armed) return true;
    String msg = util.strip(message);
    for (String t : triggers) {
        if (msg.contains(t)) { sendInTicks = 20; armed = false; break; }
    }
    return true;
}
 
void onPreUpdate() {
    if (sendInTicks < 0) return;
    if (sendInTicks == 0) client.chat("gg");
    sendInTicks--;
}
 
void onWorldJoin(Entity e) {
    if (e.isUser) { armed = true; sendInTicks = -1; }
}

Step 6 Add GUI settings

Register settings in onLoad(), read them anywhere with scriptName as the first argument.

void onLoad() {
    modules.registerSlider("Delay", 1.0, 0.0, 5.0, 0.1);
    modules.registerButton("Once per game", true);
}
 
// In onChat, read the delay:
double seconds = modules.getSlider(scriptName, "Delay");
sendInTicks = (int) Math.round(seconds * 20.0);

Finished Auto GG

    if (once && !armed) return true;

            armed = false;
            break;
        }
    }
    return true;
}

    if (sendInTicks == 0) client.chat(message);
    sendInTicks--;
}
 
void onWorldJoin(Entity e) {

}

Packets

Serverbound (you send) = C.., extends CPacket. Clientbound (server sends) = S.., extends SPacket.

Common packets

PacketDescription
C03Position/look. Fields: Vec3 position, float yaw/pitch, boolean ground
C0AArm swing
C0BEntity action (sprint start/stop, sneak, etc)
S08Server teleport. Fields: Vec3 position, float yaw/pitch
S12Entity velocity. Fields: int entityId, Vec3 motion
S02Chat message from server

Example cancel server knockback

boolean onPacketReceived(SPacket p) {
    if (p instanceof S12) {
        S12 v = (S12) p;
        if (v.entityId == client.getPlayer().entityId) return false;
    }
    return true;
}

Debugging

  • Hook not firing? Check the method name and parameter count exactly. A typo = silently never called.
  • Compile error? Chat shows the error type and line number. Fix that line and reload.
  • Never block the game thread. No Thread.sleep, no busy loops, no network on the main thread. Use tick countdowns in onPreUpdate for delays, and client.async() for heavy work.
  • Register settings in onLoad, not onEnable. Registering the same setting repeatedly is a common mistake.
  • Always return true from cancelable hooks when you're not blocking, or you'll accidentally eat events.
  • Clean up in onDisable reset timers and flags so toggling off doesn't leave pending actions.

Using AI to Write Scripts

You don't need to know Java to make Jetsidian scripts. You can hand an AI assistant like Claude the full scripting API below, describe what you want in plain English, and paste the code it writes straight into a .java file. The prompt box holds everything the AI needs to understand how Jetsidian scripts work.

You still need a JDK installed (see Setup) so the client can compile what the AI writes. The AI only writes the code the client still compiles and runs it locally.

Step by step

  1. Click Copy on the prompt box below to copy the whole Jetsidian API context.
  2. Go to claude.ai and paste it into a new chat.
  3. At the bottom of the prompt (where it says NOW WRITE ME A SCRIPT THAT:) describe what you want in plain English.
  4. Send it, then copy the Java code Claude writes back.
  5. Make a new file in your scripts folder <your minecraft folder>/keystrokes/scripts/ named something like MyScript.java, and paste the code in.
  6. In game, reload scripts, then toggle your new module on in the GUI and test it.
  7. If it doesn't compile, copy the error from your chat back to Claude and ask it to fix it.

Jetsidian AI Prompt 
You are helping me write a script for Jetsidian, an injectable Minecraft client. Read this whole spec, then write me ONE script.

HOW SCRIPTS WORK
- A script is a single .java file. The client compiles it at runtime and turns it into a toggleable module.
- I paste ONLY the class body: fields and methods. No class declaration, no imports, no package line.
- Hooks are wired up by method name + parameter count. No annotations or registration. A misspelled hook name silently never runs.
- Output ONLY the Java code for one script. No explanation, no markdown code fences.

HARD RULES
- Never block the game thread: no Thread.sleep, no while-true loops, no networking on the main thread.

- Cancelable hooks return a boolean: return true to allow the event, false to block it. Always return true when you are not blocking.
- Reset timers/flags in onDisable() so toggling off leaves nothing pending.
- Colours are ARGB ints, 0xAARRGGBB (0xFF00E5FF = solid cyan, 0x8000E5FF = 50% cyan). Chat colour codes use &: &a green, &c red, &e yellow, &b aqua.

String[] triggers = { "Winner:", "1st Killer", " won the game", "1st Place" };
int sendInTicks = -1;
boolean armed = true;

void onLoad() {
    modules.registerSlider("Delay", 1.0, 0.0, 5.0, 0.1);
    modules.registerButton("Once per game", true);
}

void onEnable()  { client.print("&aAutoGG on"); }
void onDisable() { sendInTicks = -1; }

boolean onChat(String line) {
    boolean once = modules.getButton(scriptName, "Once per game");
    if (once && !armed) return true;
    String msg = util.strip(line);
    for (String t : triggers) {
        if (msg.contains(t)) {
            double seconds = modules.getSlider(scriptName, "Delay");
            sendInTicks = (int) Math.round(seconds * 20.0);
            armed = false;
            break;
        }
    }
    return true;
}

    if (sendInTicks < 0) return;
    if (sendInTicks == 0) client.chat("gg");
    sendInTicks--;
}

void onWorldJoin(Entity e) {
    if (e.isUser) { armed = true; sendInTicks = -1; }

Example requests

Paste one of these (or your own) at the very end of the prompt, right after NOW WRITE ME A SCRIPT THAT:

  • "types 'gg' in chat 2 seconds after a game ends, once per game, with a slider for the delay"
  • "draws a HUD watermark in the top-left showing my username and current FPS"
  • "shows ESP boxes and tracers on every other player in cyan"
  • "plays a sound and prints a red warning in my chat when my health drops below 6"
  • "auto-sprints whenever I'm holding forward"
  • "counts how many players are within 5 blocks of me and shows the number on my HUD"
  • "silently aims at the current KillAura target"

Tips for better results

  • Be specific. Give the exact trigger text, delay, keybind, colours, and any settings you want. "when I see 'Victory!' wait 1 second then type gg" beats "auto gg".
  • Ask for GUI settings. Request sliders/buttons for numbers you might tweak, so you can adjust in-game without editing code.
  • One script at a time. Remind it to output only the class body no imports, no class declaration, no markdown fences.
  • Iterate. Get one feature working, test it, then ask for the next feature in the same chat so it keeps your context.
  • Paste errors back. If a compile error shows in chat, give Claude the exact error and line it usually fixes it in one try.
  • Name your colours. Tell it the ARGB colours (like 0xFF00E5FF) or chat codes (like &a) you want so the output looks how you expect.
The AI can make mistakes and doesn't know about server-specific messages or game modes. Always test scripts yourself and double-check anything before relying on it.
